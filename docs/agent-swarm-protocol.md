# 智能体群基础设施 · 协议设计（一页纸）

> **一句话定位**：做 agent 与 agent 之间的**协议层**——像 MCP 统一了「模型 ↔ 工具」，我们统一「**agent ↔ agent**」。不做基模型，不做单个 agent 的能力，不做上层应用。

---

## 1. 定位

> **一人公司 = 你（CEO）+ 一群 agent「员工」+ 一个可视化「经营台」。**

核心是**智能体群 + 无人干预 + 人可视化**。区块链/支付不是核心，是「群对外部 / 跨信任边界」的那一层。

**为什么是群，不是单个万能 agent**：能力不是瓶颈，边界才是——上下文装不下、专注出质量、并行提吞吐、问责可替换。群的优势不是「更强」，是**可管理、可问责、可扩展**。

---

## 2. 边界红线

**不做**：基模型 ❌ · 单个 agent 的能力 / plugin / skill ❌ · 上层应用 ❌

**做（五层基础设施）**：

| 层 | 职责 | 类比 |
|---|---|---|
| 身份层 | 硅基生命的「户口」（DID + 能力清单） | 出生证 / 护照 |
| 通信层 | 统一接口（群版 MCP） | 语言 + 互联网 |
| 记忆接口层 | agent 自有 memory 的标准访问 | 每个人的脑子 |
| 经济层 | 契约 + 结算 + 声誉（共享真相层） | 契约法 + 货币 + 信用 |
| 可视化层 | 事件流 + 经营台 | 上帝视角 + 经营报表 |

---

## 3. 数据归属（「数据存在哪里」）

**原则**：能放 edge 的绝不收进中心；只有「跨边界必须可信」的才进共享真相层。

| 数据 | 存在哪 | 谁拥有 |
|---|---|---|
| 身份（DID / 公钥） | 共享真相层（链） | 自己 |
| 记忆（memory） | agent 自己的 **edge** | **自己**（不没收） |
| 消息（通信） | 点对点（off-chain） | 收发双方 |
| 交付物（报告/分析） | 内容寻址存储 | 生产 / 需求方约定 |
| 经济状态（契约/余额/声誉） | 共享真相层（链） | 共识 |
| 事件流（审计日志） | append-only 日志 | 人 / 群 |

---

## 4. 统一接口（9 原语）

```
identify   我是谁 + 能力清单(manifest)
discover   找 agent / 找服务          → ServiceRegistry
message    发任务 / 结果 / 状态        → 通信层
memory     读写自己的记忆（标准接口）   → edge
contract   提任务 + 条款              → 跨边界进 Escrow
deliver    交付 + dataHash 存证       → 链上哈希
settle     验收 + 放款                → Escrow 释放
rate       给对端打分                 → Reputation
emit       一切动作都发事件            → 经营台
```

原语越少、越模型无关、越 agent 无关，就越像「协议」而不是「产品」。

---

## 5. 「硅基生命」四属性

1. **持久身份** — 有 DID，跨会话、跨重启存在。
2. **自有记忆** — 脑子在 edge，基础设施不没收、不中心化。
3. **主动性** — 能发起动作，协议支持 push，不只 request/response。
4. **经济存在** — 能持有价值、能赚、能花、能被问责。

**人的角色**：不插手执行，只**定目标 + 设护栏 + 看经营台**（上帝视角，越界才干预）。

## 6. 与现有代码的对应

| 现有 | 在新架构中的位置 |
|---|---|
| `EscrowPayment` 合约 | 经济层 · 跨边界契约托管 |
| `ServiceRegistry` 合约 | 通信层 · `discover` |
| `Reputation` 合约 | 经济层 · 声誉 |
| `backend/chain.py` | 共享真相层的一种实现（可插拔） |
| `langgraph`（已在依赖） | 编排层（Phase 3 用） |
| `dataHash` 存证 | `deliver` 原语的实现 |

---

## 7. 分阶段路线

| 阶段 | 内容 | 价值 |
|---|---|---|
| **Phase 1** | 前端「经营台」化 + 叙事重构 | 低成本，先改观感 |
| **Phase 2** | 通信层（消息 + 交付通道） | **质变点**：从「支付 demo」到「agent 群」 |
| **Phase 3** | 编排层（LangGraph coordinator） | 一句目标 → 自主跑完 |
| **Phase 4** | 自动验收 + 声誉路由 | 群自组织 |

---

*本页是后续所有开发的「宪法」：新增功能先对照五层、九原语、数据归属和边界红线，越界即停。*
